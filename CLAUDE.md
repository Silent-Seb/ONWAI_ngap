# ONWAI_ngap — notes for Claude Code

Rust NGAP (3GPP TS 38.413 Rel-19) codec for the AMF side, generated from the ASN.1 in the spec. **Read `README.md`
first**: it holds the plan, the repo layout, the implementation checklist (keep it ticked) and the verification strategy.

## Rules of the repo
- `crates/ngap-types` is **generated and committed**. Never edit it by hand: fix `crates/ngap-codegen` (or the
  runtime `crates/ngap-aper`), run `cargo xtask gen`, and `cargo xtask check` must report "generated code is up to date".
- Hand-written crates: `ngap-aper`, `ngap-codegen`, `onwai-ngap`, `xtask`. `unsafe` is forbidden.
- The 3GPP Word document is **not vendored** (`specs/38413-j40.docx`, git-ignored; `NGAP_SPEC_DOCX` / `--docx`), but the extracted
  `specs/asn1/*.asn` are **committed and never edited by hand**: re-run `cargo xtask extract-asn` (`git diff` must be empty); their
  SHA-256 are pinned in `codegen/spec-source.toml` and checked by `ngap-codegen/tests/spec_modules.rs`.
- Scope is **codec only** (no SCTP, no state machines, no NAS). Don't grow it without asking.
- After changing the generator or runtime: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`
  (the generated crate opts out), `cargo test --workspace`, `cargo xtask check`.
- The whole `ngap-types` crate type-checks in ~1 min at ~660 MB, so `cargo test --workspace` needs no slicing; on a small
  host (about 2 GB RAM) add `-j2`.
- Generated Rust must not use proc-macro derives beyond `Debug, Clone, PartialEq, Eq`.
- `ngap-aper` is checked against vectors from an independent encoder (`tools/gen_aper_vectors.py`, asn1tools). When a test
  and the oracle disagree, check X.691 before changing either: the oracle is wrong for `INTEGER (lb..MAX)` and lacks
  size-extension for bit/character strings (those tests are hand-derived on purpose).
- `ngap_codegen::asn1` parses only the NGAP dialect on purpose. If a new spec release needs another construct, extend the
  parser/AST *and* the census cross-checks in `tests/parse_ngap.rs`; do not loosen the gates. `cargo xtask stats` shows the census.
- `ngap_codegen::ir` must stay derived from the spec: do not hard-code message or IE names in the resolver. Container shapes
  come from instantiating `NGAP-Containers`; if a new release changes them, `build_ir` errors (that is the point).
- `ngap-types` source is never edited; its `tests/` and `examples/` are hand-written. `cargo xtask gen` rewrites only files that
  carry the `@generated by ngap-codegen` marker. Golden vectors (`crates/ngap-types/tests/vectors.txt`) come from
  `tools/gen_ngap_vectors.py` (needs Python + asn1tools and `tools/oracle_asn.py`; see the script headers) and are committed, so
  tests do not need Python.
- Rust 2024 reserves `gen`: no module, function or variable of that name.
- The emitter derives behaviour from the IR (`SetKind`, tables), not from class names; the few protocol names it does rely on
  (`Criticality`, `ProcedureCode`, `PrivateIE-ID`, the three PDU wrapper field names) are checked and reported if they change.
- `onwai-ngap` (facade) depends on the generated accessors (`ie_ids()`, `wire_ie_ids`, `PROCEDURE_CODES`, ...). Its clause-10 table is
  in the README ("Decode diagnostics"); change the table, `crates/onwai-ngap/tests/diagnostics.rs` and the code together. It reads
  the envelope before decoding the body so errors keep their procedure context.
- `testdata/` is **generated** by `cargo xtask vectors` (crate `ngap-testgen`, which samples valid APER from the IR without using
  `ngap-types`). Never edit it; `cargo xtask check` and `ngap-testgen/tests/vectors_current.rs` fail when it is stale. After
  changing the sampler, regenerate and run `tools/check_vectors.py` (see `docs/regenerating.md`) so the oracle still agrees.
- `tools/oracle_asn.py` may only make rewrites that do not change the PER encoding (it replaces `INTEGER (1..30|40|181)` by its span
  because X.691 encodes the span).
- Robustness: `onwai-ngap/tests/mutation.rs` (`NGAP_SEED`, `NGAP_MUTATIONS`). A failure prints the PDU and the mutation; fix the
  decoder, do not weaken the property.

## Future work: optional `serde` feature (decided 2026-11-28: skip for now, no consumer yet)
Do it only when something needs JSON (structured logs, a decoded-PDU dump for tooling or a UI, JSON fixtures); `Debug` covers the rest.
Decisions to take first:
1. **Mechanism.** A: `#[cfg_attr(feature = "serde", derive(serde::Serialize))]` on the generated types (simple; off by default; needs the
   "no proc-macro derives" rule amended to "except behind the `serde` feature"), or B: the emitter writes the `impl Serialize` code
   itself (keeps the rule; much more generated code and generator work). Recommended: A. `ngap-aper` types (`BitString`, `RawIe`,
   `Contained<T>`, `UnknownIes`) need impls too.
2. **Shape of the JSON** (a versioned public format once people depend on it): field/variant names (Rust snake_case or the spec's ASN.1
   names, e.g. `pLMNIdentity`); binary data as hex / base64 / byte array (a `BitString` also needs its bit length); `Contained<T>` as raw
   hex or the decoded value; unknown IEs (id, criticality, raw bytes); enums by name or number, and extension values.
3. **Serialize only, or Deserialize too.** Recommended: `Serialize` only. A derived `Deserialize` would bypass the range/size checks of the
   newtypes and allow values that fail later at encode time; doing it properly needs validated constructors.
4. CI: build and test with the feature on (a job), keep it off by default, and check `cargo deny` still passes.
